① MBが解く問題と機能・理屈のマップ

「何をしたいのか → どの機能を使うのか → なぜそれで解けるのか」の構造を先に整理します。個別の操作はこの地図を持った状態で覚えると定着が速くなります。

🎯 やりたいこと
🔧 解法機能
⚙️ 理屈（なぜそれで解けるか）
人間のMocapを
別骨格のCGキャラに転送したい
→
Characterize + Retarget
→
両方を「共通の参照ポーズ（T-pose）」で定義することで、骨格の長さ・向きの差異を吸収できる。異なる骨格を同じ中間言語に変換する構造。
リターゲット後の不自然な動きを
修正したい
→
Control Rig（FBIK）
→
IKは「末端位置を指定 → 間の関節角度をソルバーが逆算」する仕組み。「手をここに置きたい」という意図1点だけで全腕が解ける。数百フレームのボーンを直接弄らずに済む。
足が床をぬるぬるスライドしてしまう
→
Pinning（Translation）
→
エフェクターをワールド座標の特定点に「固定（Pin）」する。体の重心が移動しても、Pinされた足はその座標から動かない。足が「地面に刺さっている」状態を作れる。
足が床に刺さる・浮いてしまう
→
Floor Contact
→
床面との接触制約を自動計算し、足が設定高さ（Y値）より下に行かないようにクランプする。地形が変わっても追従できる。
複数のMocapクリップを一本のシーンで繋ぎたい
→

→
NLE（非線形編集）構造で元クリップを変えずにタイムライン上に並べ・ブレンドできる。Premiereのタイムラインと同じ概念。
編集を確定してMayaに渡したい
→
Plot to Skeleton → FBX
→
Control Rigはリアルタイム計算レイヤー。Plotでその計算結果をボーンのキーフレームとして「確定＝焼き付ける」。FBXはMBとMayaの共通言語。

④ テイク（Take）システム

MotionBuilderでは「アニメーションのひとまとまり」を テイク と呼びます。1シーンに複数のテイクを持てます。

  • Transportバー右側のプルダウンから切り替え・追加が可能
  • テイクごとにアニメーションカーブが独立している
  • Mocapデータを読み込むと "Take 001" などのテイクとして入る
  • FBX書き出し時に「どのテイクを書き出すか」を選べる

⑤ あなたが知っているワークフローを整理する

操作手順の丸暗記より「各ステップで何をしているか」を言語化する方が定着します。

1

Mocapデータ読み込み ✅ 既知

FBX / C3D などでキャプチャデータを開く。テイクとして入ってくることが多い。

2

Mocap側のキャラクタライズ ✅ 既知

骨格のボーンをCharacter Definitionにマッピング。「このボーンが腰、これが左手首…」とMBに教える。T-poseに対する相対的な位置関係として記録される。

3

CGモデル側のキャラクタライズ ✅ 既知

受け側のCGキャラも同様にCharacter Definitionでマッピング。これで「同じ参照系」を持つことになる。

4

リターゲット（Input設定）✅ 既知

CGモデルのキャラクターに「入力元＝Mocapのキャラクター」を指定。共通の参照系を使って体型差を補正しながらモーションが転送される。

5

Plot to Skeleton（ベイク）✅ 既知

Control Rigやリターゲットはリアルタイム計算。Plotすることでその結果をボーンのキーフレームとして焼き付ける。この後FBXで書き出してMayaへ。

6

Control Rig で修正してからPlot 🎯 次の目標

リターゲット後・Plot前にControl Rigを使うとIK/FKエフェクターでモーションを直接修正できる。ここが次の章のテーマ。

📌

Control Rigの位置づけ： Characterize → Retarget → （ここでControl Rig編集） → Plot。「リターゲット済みアニメーションの微調整ツール」。編集を確定させるにはPlotが必要。

⑥ アニメ制作の全体地図 — Mocap修正とゼロ制作

MB でのアニメーション制作には大きく2つのモードがあります。あなたが仕事でやってきたのは左側（Mocap 修正）。右側（ゼロから制作）も、実は同じ道具の上に載っています。ここでは個別の操作には入らず、地図だけ持って次のページへ進みます。

🎥 Mocap 修正

  • 入力：Mocap データ（動きの素材）がある
  • やること：問題箇所だけを直す。作業量は比較的少ない
  • 強み：リアルな重量感・慣性が最初から入っている
  • 向く場面：大量データ処理・人の自然な動き・実写リファレンスあり

✏️ ゼロから制作

  • 入力：なし。白紙からポーズを組み立てる
  • やること：全フレームを自分で設計する。作業量は多い
  • 強み：意図を100%反映できる。物理法則を無視してよい
  • 向く場面：完全オリジナル動作・誇張表現・Mocap が撮れない動き
🤝 どちらでも変わらない共通構造
Characterize → Control Rig 作成 → ポーズ・動きの指定 → Plot（確定） → FBX 書き出し

構造が同じということは、Control Rig の使い方を一度覚えれば、Mocap 修正にもゼロ制作にも使い回せるということです。変わるのは「入力の素材があるかないか」と「元の動きをどれだけ残すか（Reach）」だけ。

⑦ Story ウィンドウ（NLE）

複数テイクを並べて編集・ブレンドするための非線形エディタです。Premiereのタイムラインと同じ構造で考えると掴みやすい。

  • 開き方： Window → Story
  • キャラクタートラックにクリップを並べて結合できる
  • クリップのつなぎ目にブレンドを入れると滑らかに繋がる
  • Story から Plot すると複数クリップを1テイクに統合できる
  • 元クリップは変更されない（非破壊） — これがNLEの利点
