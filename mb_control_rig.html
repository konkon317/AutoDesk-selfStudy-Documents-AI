① なぜControl Rigが必要か

Mocapデータは「何百フレーム × 何十ボーン」のキーフレーム群として存在します。これを直接修正しようとすると：

ボーン直接編集の限界

  • 手の位置を変えたら肩・肘・手首を全部合わせ直す必要がある
  • 連続フレームの修正は事実上不可能な物量
  • 編集が「手段（ジョイント角度）」の操作になってしまう

Control Rigで解決すること

  • 「手をここに置きたい」→ Hand Effectorを1点移動するだけ
  • IKソルバーが肩・肘・手首の角度を自動計算
  • 編集が「意図（エフェクター位置）」の指定になる

Control Rigとは「ボーンへの直接指示から、意図の指定への抽象化」です。修正の粒度を「ボーン1本ずつ」から「体のパーツの目標位置」に変えます。

② IKの理屈（FKとの比較）

IKとFKは「骨格を動かす計算の方向」が逆です。これを先に理解するとエフェクターの操作が直感的になります。

💡

FBIKとは： MotionBuilderのControl RigはFull Body IK（FBIK）を使います。通常のIKが「腕1本」を解くのに対し、FBIKは全身を同時に解きます。Hips Effectorを動かすと体全体の重心が移動し、すべてのエフェクターとの整合が自動的に保たれます。

③ Control Rigの構造（レイヤー図解）

重要： Control RigはLayer 1のボーンを直接編集しません。PlotでLayer 3の計算結果がLayer 1に焼き付けられます。Plot前はUndoで戻せます。

④ エフェクターの種類と役割

🧠
Head IK
頭の向き・位置。視線方向の修正に。
🫁
Chest IK
胸の向き。上半身全体のねじれ修正に。
⬡
Hips IK
重心・骨盤の位置と向き。全身の基点。最もよく使う。
✋
L/R Hand IK
手の位置と向き。腕全体が追従する。壁・机への接触修正に。
👟
L/R Foot IK
足の位置と向き。フットプラント修正の核心。
💪
Shoulders IK
肩が不自然に上がるMocapの修正に。上半身の自然さに関わる。
🔷
L/R Elbow AUX
肘の曲がる方向（ポール）を制御。肘の向きがおかしいときに使う。
🔷
L/R Knee AUX
膝の曲がる方向を制御。内股・ガニ股の修正に。

⑤ Reach — 上書き強度を制御する

Reachは「Control RigのエフェクターがMocapをどの程度上書きするか」の重み付けです。エフェクターごとに独立して設定できます。

Reach = 0%（元Mocap通り） Reach = 100%（完全上書き）
元Mocapそのまま← キーで徐々に上げる →エフェクター完全優先
Reach値意味使いどころ
0%Control Rigを使わない「この部位は修正不要」を明示するとき
50%MocapとControl Rigの中間自然な移行、徐々に修正を加えるとき
100%エフェクターに完全に従うPinningと組み合わせた修正、向きを固定するとき

UIでの実際の名前（Properties パネル）

「Reach」は概念上の呼び方で、エフェクターを選択したときの Properties パネルでは以下の名前で表示されます。

UIの名前 概念上の呼び方 何をするか
IK Blend T Reach（位置） エフェクターのIK位置がFKソースをどれだけ上書きするか。0%=FK側、100%=エフェクター優先
IK Blend R Reach（回転） エフェクターのIK回転がFKソースをどれだけ上書きするか。T と R は独立して設定できる
IK Pull （Reachとは別の概念） エフェクターを動かしたとき肘・膝などの中間ボーンをどれだけ引き寄せるか。ブレンドではなくチェーンの硬さ
ソースアニメーションがないと IK Blend を変えても変化が見えない
IK Blend T/R は「FK側（Mocapなどのソース）とエフェクター位置の合成比率」です。Mocapデータがない状態ではブレンド元が存在しないため、値を変えても見かけ上ほとんど変わりません。ゼロから手付けする場合は T/R とも 100% のまま放置して、エフェクターを動かすことに集中すればOKです。
🖐

試してみる： Head Effector の Translation Reach を 0% → 100% に変えながら再生する。頭がMocapの動きからエフェクター位置に「引っ張られる」様子が確認できる。

⑥ Pinning — 足を地面に固定する

Pinningは「エフェクターをワールド空間の特定座標に固定する」仕組みです。足スライド（フットプラント問題）の修正が主な用途です。

Translation Pinning（位置固定）

エフェクターのXYZ位置をワールド空間に固定する。体の重心が動いても足はその座標に留まる。「地面に刺さっている」状態を作れる。

Rotation Pinning（向き固定）

エフェクターの向きを固定する。足の向きが回転しないようにするとき。Translation Pinningと組み合わせることが多い。

フットプラント修正の手順

1

着地フレームを特定する

タイムラインを確認し、足が完全に着地しているフレームを探す。

2

着地フレームでTranslation PinをONにする

Character Controls → Foot Effector → Translation Pin をON。キーフレームが自動で打たれる。

3

離地フレームでPinをOFFにする

足が地面から離れるフレームでPinをOFF。ここからは元のMocapの動きに戻る。

4

全ステップ分繰り返す

歩行サイクルのすべてのステップ分繰り返して精度を上げる。

⑦ Floor Contact — 床めり込みを防ぐ

Pinningが「特定フレームで足を固定する手動制御」なのに対し、Floor Contactは「床面に当たったら自動的に止まる動的制約」です。

設定場所

  • Character Controls → Character Properties
  • Foot Contact → ON
  • Floor Y（床の高さ）を設定
  • Contact Height（接触判定の高さ）を調整

Pinningとの使い分け

観点PinningFloor Contact
制御方法手動（フレームごと）自動
用途足スライド修正床めり込み防止
柔軟性高い床のみ

⑧ 実践ワークフロー（修正からPlotまで）

1

Control Rigを作成する

Character Controls → キャラクターを選択 → 「IK/FK Control Rig」を作成。作成後すぐにエフェクターが使える。

2

問題箇所を特定し、修正部位を絞る

再生しながら「足？ 腰？ 手？」と修正箇所を決める。1セッション1テーマで集中する。

3

関係するエフェクターのReachを100%にする

修正したい部位だけReachを上げる。修正しない部位は0%のまま。

4

エフェクターを動かして修正する

エフェクターをドラッグで移動・回転。Pinningが必要なら設定。

5

確認してPlotする

再生して確認。問題なければ Character Controls → Plot → Plot to Skeleton。

6

FBXで書き出す

File → Export → FBX。アニメーション・スケルトンにチェックが入っているか確認。

📌

Plot前のチェック： PlotするとControl Rigの編集内容がボーンキーフレームに確定されます。Plot後に再修正するにはControl Rigを再作成が必要。修正が完成してからPlotするようにしましょう。
